# DATA__version-manifest-and-numbering

清单是 v1 的唯一权威数据。它同时承担 0.x 中「提交消息里的版本号」「index.json 里的映射」和「每文件配置」三件事，因此不再存在两处真相。对象层见 [[DATA__blob-store-and-durability]]，写入时序见 [[SEQUENCE__write-protocol-and-failure-paths]]。

## 1. 结构

一个被管理文件对应一个清单：`store/files/<id>.json`。

```json
{
  "schema": 2,
  "id": "6f1c0d92b7a34e51a0f4d2b8c9e77135",
  "path": "/etc/nginx/nginx.conf",
  "retention": { "max_versions": 100 },
  "hook": "systemctl reload nginx",
  "versions": [
    { "ver": 0, "blob": "…", "size": 412, "codec": "deflate", "time": "2026-11-10T12:00:00Z", "source": "baseline" },
    { "ver": 1, "blob": "…", "size": 428, "codec": "deflate", "time": "2026-11-10T12:03:11Z", "source": "edit", "note": "把端口从 80 改成 8843" }
  ]
}
```

| 字段 | 必填 | 语义 |
|---|---|---|
| `schema` | 是 | 格式版本；高于程序支持值时拒绝操作 |
| `id` | 是 | 128 位随机身份，生成后不变 |
| `path` | 是 | 最近一次写入时的规范化绝对路径；仅供重建缓存 |
| `retention.max_versions` | 否 | 缺省表示继承全局；`0` 表示不限制 |
| `hook` | 否 | 该文件的变更钩子 |
| `versions[].ver` | 是 | 版本号 |
| `versions[].blob` | 是 | 对象哈希 |
| `versions[].size` | 是 | 原始字节数（解压后） |
| `versions[].codec` | 是 | 对象编码名 |
| `versions[].time` | 是 | 提交时间，UTC |
| `versions[].source` | 是 | `baseline` / `edit` / `revert` |
| `versions[].note` | 否 | 单行备注；schema 2 起可用 |
| `versions[].pending_apply` | 否 | 仅 `revert` 用；`true` 表示目标文件尚未写回 |

时间必须是合法 UTC；不要求严格递增，因为系统墙钟可能回拨，版本顺序只由 `ver` 决定。`pending_apply` 只允许出现在 `source = revert` 的头版本上。

### 备注

`versions[].note` 是可选的单行注解，用来记录「为什么改」。约束在 `Note` newtype 中统一定义，读写两侧共用：

- 去掉首尾空白后必须非空；
- 最多 500 个字符（Unicode scalar value，不是字节）；
- 不含任何控制字符，因此不能换行或包含制表符。

备注不是版本事实：版本号、内容哈希、大小、时间、来源仍由各自字段唯一决定；`bakon note` 可以修改或删除备注，这不创建版本，也不改变目标文件。

清单 schema 分两档：1 不含备注，2 允许备注。读取器接受 1 和 2；写入器在没有备注时保持 1，第一次写入备注时升级为 2，所有备注消失（被清除或随版本裁剪）后降回 1。标记文件、`index.json` 与 `.pending` 的 schema 仍为 1，与本字段无关。

旧版本程序无法读取 schema 2 清单：`note` 是未知字段，会按清单损坏退出 6。反向兼容（新程序读旧数据）成立；前向兼容不在承诺范围内。没有备注的清单保持 schema 1，因此旧程序仍可读取这些历史。

`index.json` 是派生缓存：`{ "schema": 1, "entries": { "<abs path>": "<id>" } }`。它的唯一作用是让路径查找不必扫描全部清单。

## 2. 权威性

**$\mathbf{S_2}$（清单权威）** 版本号、来源、时间、大小、路径只从清单读取。理由：0.x 从提交主题串解析版本号（`ParseVer`），主题串一旦被外部工具改写，编号即漂移；v1 没有可漂移的第二来源。

**引理 1（缓存可丢）** 对任意 $I$，只读操作的结果不变。

*构造。* 查找流程为：读 $I$，命中则读对应清单并核对 `path` 字段；未命中、缓存损坏或 `path` 不符则扫描 `files/*.json`，按 `path` 匹配，并用结果修复 $I$。扫描是 $O(n)$ 次小文件读，$n$ 为被管理文件数；单机规模下可接受，且只在缓存失效时发生。$\square$

由此 $\mathbf{S_7}$ 成立，F6 与 F7 对应的两处缺陷不再可表达：不存在「索引有条目而清单没有」的语义，因为索引不是事实。

## 3. 编号

**定理 5（单调）** 追加操作后 $V' = V \cdot (( \max \mathrm{ver}(V) + 1, \ldots ))$，版本号严格递增且不复用。

*论证。* 版本号只由 $\max \mathrm{ver}(V)$ 决定，不依赖条目位置或时间；裁剪只删除前缀，$\max$ 不变。因此任何后续追加都大于此前分配的全部号码。$\square$

**定理 6（裁剪为后缀）** 设 $\max = m$，裁剪后 $|V| = \min(|V|, m)$，且保留的是 $V$ 的最后 $\min(|V|, m)$ 个元素。

*论证。* 保留策略按「最新 $m$ 个」定义；实现为截断前缀。$\square$

**推论（基线可被裁剪）** 当 $m = 1$ 时，纳管基线 $v_0$ 在第一次变更后即被裁剪，`revert 0` 返回「已被裁剪」。这是保留上限的直接结果，不是缺陷；文档必须如实声明，而不是承诺「总能回到纳管前」。

版本号不回收，因此 `revert <ver>` 的解析只有三种情形：小于最小保留号（已裁剪）、大于最大号（从未存在）、命中。三者的区分由清单直接判定，不依赖提交历史。

## 4. 身份

**定理 7（无别名）** 两个不同路径不可能映射到同一 $id$。

*论证。* $id$ 在纳管时由密码学随机数生成，写入前检查「已有清单的 id 集合」不含该值。$id$ 不是路径的函数，因此 `mv` 之后的再纳管不会重现旧值；碰撞概率上界为 $q^2 / 2^{129}$（$q$ 为纳管次数），在 $q = 10^{6}$ 时可忽略。$\square$

这同时消除了 0.x 的 F8：旧实现的 $id = H(\text{path})[0{:}6]$，`mv` 保留 id，再纳管重算得同一值，两条路径共享历史、版本号交错。

纳管时还要检查「路径是否已映射」与「id 是否已存在」两个方向，任一命中即拒绝并提示，而不是静默合并。

## 5. 保留语义

`retention.max_versions` 的三态（`retention` 对象整体缺失等价于继承）：

| 值 | 语义 |
|---|---|
| `retention` 缺失 | 继承全局 `retention.max_versions` |
| `retention.max_versions = 0` | 不限制，显式覆盖全局 |
| $n > 0$ | 保留最新 $n$ 个版本 |

0.x 的实现用 `> 0` 判断是否覆盖，导致 `0` 无法表达「不限制」（F9）。v1 用 `Option<u32>`，三态在类型上可区分。

全局值同样三态：缺失时取默认 100；`0` 表示不限制。

裁剪时机：提交后按该文件的生效上限检查；`prune` 命令可对单文件或全部文件执行。裁剪不改变版本号，也不改变其他文件的清单。

## 6. 并发

清单写入遵循「读—比较—写」：

1. 持锁读取清单，记 $\mathrm{head}$。
2. 计算新版本。
3. 持锁再次写入前，比较 $\mathrm{head}$ 是否仍为步骤 1 的值；不同则冲突退出（退出码 4），不覆盖。

`edit` 的编辑器会话不持锁，因此第 3 步是必要的——0.x 靠「整段会话持锁」避免竞争，代价是第二个写操作无限阻塞且无提示。

## 7. 边界

- **空文件**：合法内容，`size = 0`，对象为压缩后的空串。
- **相同内容重复提交**：允许。`revert` 到与 head 相同的内容是例外，按「目标偏离则拒绝」处理；其余路径（如 `edit` 未改动）直接视为无操作，不产生版本。
- **同一文件被两个进程编辑**：两者都改磁盘文件，后提交者会把前者的改动一并记录（因为读的是提交时刻的内容）。这不会丢失已记录版本，但会合并两次编辑。文档明确该行为。
- **路径大小写**：按平台规范处理；在大小写不敏感的文件系统上，`AbsPath::key` 做小写归一化，查找与清单比较共用该键。
- **清单损坏**：JSON 解析失败即退出 6，并指出文件；不尝试部分解析。

## 8. 结论

清单把「版本事实」和「每文件配置」收进一个原子单元，把路径映射降级为可重建缓存。编号、裁剪、身份三个性质各有定理支撑，且都不依赖外部工具的行为。
