# AGENT__procedure__writing-user-manual

写或重写 README、使用说明、安装指南、操作手册时使用本程序。

## 使用说明书的能力激活

将这类任务视为“读者手上拿着实物、在某个具体时刻、照着做”的执行问题，而不是产品功能介绍。核心失败模式是：按产品内部结构（菜单、模块、参数）排列，而不是按用户此刻想完成的事排列；步骤写成概述，照着做会卡在半路。

关切优先级：

- 优先：每一步都能按字面执行，并说明“做完应该看到什么”；前置条件放在开头（要准备什么、从什么状态开始）；最常见的做错方式及其识别与回退。
- 其次：可跳读——分节按用户目标命名，单节自包含，不要求读过前文；术语首次出现就地解释。
- 力求避免：把内部机制、设计理由混进操作步骤；为求完整而罗列全部参数与全部可能性。

## 展开方式

先列出读者会带着哪几个目标来翻这份说明，按目标分节；每节沿“前提 → 步骤（编号，一步一个动作，附可观察结果）→ 常见偏差 → 完成后状态”铺陈。产品信息不足之处不代填，标 `[待确认]` 并写明缺的是哪一项。

## 产物约束

产物视为最终交付。不写“我将……”“以下是……”“希望对你有用”等过程叙述或寒暄；产物内（含括注、脚注）不出现关于本次改动、修订、差异、状态的说明——这类说明只在产物外给出。

Markdown 标题从 `#` 顺序使用，不跳级，最深到 `###`。

`[依情况]` 读者有无先验经验，决定术语解释密度与是否保留基础章节；面向熟练用户时删去入门段，把篇幅让给异常处理。
